Every `GET` endpoint that returns a collection is a list, and every list is paginated the same way, with opaque cursors. There are no page numbers, no offsets and no totals. A cursor is a forward-only pointer into the result set.

## Parameters

| Parameter | Type | Default | Range | Description |
| --- | --- | --- | --- | --- |
| `limit` | integer | 25 | 1 to 100 | Items per page. A value outside the range, or not an integer, is `400 invalid_limit`. |
| `cursor` | string | none | | The `next_cursor` from the previous response. Omit it to start from the first page. A cursor that is malformed, has expired, or that the endpoint did not issue is `400 cursor_invalid`. |
| `created_after` | RFC 3339 timestamp | none | | Only items created at or after this time (inclusive). Offered where the endpoint documents it. |
| `created_before` | RFC 3339 timestamp | none | | Only items created before this time (exclusive). Offered where the endpoint documents it. |

Other filters (`status` and so on) match exactly and are documented with their allowed values on each endpoint. An unknown filter value or an unknown query parameter is a `400`, never an empty list. Timestamps are RFC 3339 in UTC with a `Z` suffix, for example `2026-11-19T14:03:22.104Z`.

Lists are ordered newest first. The order is stable: items created at the same instant are ordered by `id`, so paging never skips or repeats an item.

## Response

Every list has the same envelope, including short ones such as currencies and corridors. A list is never a bare array.

```json
{
  "object": "list",
  "data": [
    { "id": "pay_01JD3X9K2M7Q", "object": "payout", "status": "completed" },
    { "id": "pay_01JD3X8H4N5R", "object": "payout", "status": "processing" }
  ],
  "has_more": true,
  "next_cursor": "eyJpZCI6InBheV8wMUpEM1g4SDRONVIifQ"
}
```

| Field | Description |
| --- | --- |
| `object` | Always `"list"`. |
| `data` | The items on this page. An empty page is `[]`. |
| `has_more` | `true` when more items exist after this page. |
| `next_cursor` | The cursor for the next page, or `null` on the last page. The key is always present. |

The last page:

```json
{
  "object": "list",
  "data": [{ "id": "pay_01JD3X7G3M4Q", "object": "payout", "status": "completed" }],
  "has_more": false,
  "next_cursor": null
}
```

## Iterating through pages

<CodeGroup>

```bash cURL
# First page
curl "https://api.antonpayments.dev/v1/payouts?limit=100" \
  -H "Authorization: DPoP $ANTON_ACCESS_TOKEN" \
  -H "DPoP: $DPOP_PROOF"

# Next page: pass the previous response's next_cursor as cursor
curl "https://api.antonpayments.dev/v1/payouts?limit=100&cursor=eyJpZCI6InBheV8wMUpEM1g4SDRONVIifQ" \
  -H "Authorization: DPoP $ANTON_ACCESS_TOKEN" \
  -H "DPoP: $DPOP_PROOF"
```

```javascript JavaScript
async function listAllPayouts(accessToken) {
  const payouts = [];
  let cursor;

  while (true) {
    const url = new URL("https://api.antonpayments.dev/v1/payouts");
    url.searchParams.set("limit", "100");
    if (cursor) url.searchParams.set("cursor", cursor);

    const response = await fetch(url, {
      headers: { Authorization: `DPoP ${accessToken}` },
    });
    const page = await response.json();
    payouts.push(...page.data);

    if (!page.has_more) break;
    cursor = page.next_cursor;
  }

  return payouts;
}
```

```php PHP
function listAllPayouts(string $accessToken): array {
    $payouts = [];
    $cursor = null;

    while (true) {
        $query = http_build_query(array_filter([
            'limit' => 100,
            'cursor' => $cursor,
        ]));

        $ch = curl_init("https://api.antonpayments.dev/v1/payouts?$query");
        curl_setopt_array($ch, [
            CURLOPT_RETURNTRANSFER => true,
            CURLOPT_HTTPHEADER => ["Authorization: DPoP $accessToken"],
        ]);
        $page = json_decode(curl_exec($ch), true);
        curl_close($ch);

        $payouts = array_merge($payouts, $page['data']);

        if (!$page['has_more']) break;
        $cursor = $page['next_cursor'];
    }

    return $payouts;
}
```

```go Go
func ListAllPayouts(accessToken string) ([]Payout, error) {
    var payouts []Payout
    cursor := ""

    for {
        u, _ := url.Parse("https://api.antonpayments.dev/v1/payouts")
        q := u.Query()
        q.Set("limit", "100")
        if cursor != "" {
            q.Set("cursor", cursor)
        }
        u.RawQuery = q.Encode()

        req, _ := http.NewRequest("GET", u.String(), nil)
        req.Header.Set("Authorization", "DPoP "+accessToken)
        resp, err := http.DefaultClient.Do(req)
        if err != nil {
            return nil, err
        }

        var page struct {
            Data       []Payout `json:"data"`
            HasMore    bool     `json:"has_more"`
            NextCursor *string  `json:"next_cursor"`
        }
        json.NewDecoder(resp.Body).Decode(&page)
        resp.Body.Close()

        payouts = append(payouts, page.Data...)

        if !page.HasMore {
            break
        }
        if page.NextCursor == nil {
            break
        }
        cursor = *page.NextCursor
    }

    return payouts, nil
}
```

## Rules

<AccordionGroup>
  <Accordion title="Use the maximum page size">
    Set `limit=100` to minimize round trips when fetching large result sets.
  </Accordion>
  <Accordion title="Stop when has_more is false">
    `has_more` (or a `null` `next_cursor`) is the only correct termination signal. Don't compare `len(data)` to `limit` — the last page may be full.
  </Accordion>
  <Accordion title="Cursors are opaque">
    Treat cursor values as opaque strings. Do not parse, modify, or construct them. Always pass the exact `next_cursor` value returned by the API.
  </Accordion>
  <Accordion title="Do not keep cursors for long">
    A cursor is only meaningful to the endpoint and the filters that issued it. Reusing one with different filters, or after a long time, can return `400 cursor_invalid`. If you get that, start again from the first page.
  </Accordion>
  <Accordion title="Treat an unknown cursor as opaque">
    The format of a cursor is not part of the API and can change. Never build one yourself.
  </Accordion>
</AccordionGroup>
