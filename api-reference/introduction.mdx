The Anton API is a REST API over HTTPS. All requests and responses are JSON. All dates are ISO 8601 UTC. All monetary amounts are **decimal strings** — never floats — to avoid rounding errors.

## Base URLs

| Environment | Base URL |
|---|---|
| Production | `https://api.antonpayments.com` |
| Sandbox | `https://api.antonpayments.dev` |

## Authentication

Every request requires an OAuth 2.0 access token (DPoP-bound) AND a per-request DPoP proof. Static API keys are not accepted on v1. See [Authentication](/authentication) for the full flow, including a copy-paste curl quickstart.

```http
Authorization: DPoP <access_token>
DPoP: <proof JWT, fresh per request>
```

Access is additionally governed by **account capabilities** and **credential scopes** (`payouts`, `intelligence`) — effective access is `scopes ∩ capabilities`, and out-of-capability calls fail with `403 capability_required` / `403 insufficient_scope`. See [Capabilities & Scopes](/capabilities).

## Conventions

- **Versioning.** The API is versioned by date, for example `2026-12-01`. Your account is pinned to the latest version when you create your first OAuth client, and every response carries an `Anton-Version` header with the version it was served at. Send `Anton-Version` on a single request to try another version on that call. An unknown version is `400 invalid_api_version`. Webhook events are rendered at your pinned version. A breaking change ships only as a new version, so an existing integration keeps working unchanged. New routes, optional fields, enum values, error codes, event types and headers can appear in any version: ignore what you do not recognise.
- **JSON.** Request bodies are `application/json`, up to 1 MB. A request with a body that is not `application/json` is `400 invalid_content_type`. The two upload endpoints (batch upload and beneficiary import) take `multipart/form-data` instead. Field names are `snake_case`. Unknown body fields, unknown query parameters and wrong types are rejected with `400`, never ignored.
- **Amounts.** Monetary values are decimal strings with a currency: `"1234.56"`, not `1234.56`. Parse them as decimals, not floats. Responses always render the currency's full precision (`"10.50"`, never `"10.5"`). `GET /v1/currencies` lists each currency's precision.
- **Timestamps.** RFC 3339 in UTC with milliseconds and a `Z` suffix: `"2026-11-19T14:03:22.104Z"`. Fields that hold a time end in `_at`. A calendar date with no time ends in `_date` and is `YYYY-MM-DD`.
- **Resources.** Every object has `id`, `object` (its type name), `livemode` (`false` in sandbox), and, where you create it, `metadata`: up to 50 string keys. Do not put personal data in metadata.
- **Identifiers.** Prefixed opaque strings: `pay_...`, `ben_...`, `ins_...`, `bat_...`, `whk_...`. A path ID with the wrong prefix or shape is `400 resource_id_invalid`, with `param` set; a well-formed ID that does not exist for your account, or belongs to another account, is `404 resource_missing`. Treat IDs as opaque.
- **Single resources.** A request for one resource returns the object itself at the top level, with no `data` wrapper. A delete returns `{"id": "...", "object": "...", "deleted": true}`.
- **Lists.** Every list is `{"object": "list", "data": [...], "has_more": ..., "next_cursor": ...}` with cursor pagination. See [Pagination](/api-reference/pagination).
- **Errors.** Every error has `type`, `code`, `message` and `request_id`. See [Errors](/api-reference/errors).
- **Download the spec.** The full OpenAPI description is at [openapi-merchant.yaml](/openapi-merchant.yaml). Use it to generate a client or import the API into a tool such as Postman.

## Response headers

| Header | On | Meaning |
| --- | --- | --- |
| `Request-Id` | Every response | Our identifier for the request (`req_...`), the same value as `error.request_id`. Quote it in support requests. It is always generated by Anton. |
| `Anton-Version` | Every `/v1` response, including `401` | The API version the response was served at. |
| `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` | Every authenticated response (left out when the limit could not be checked) | Your current rate limit window. See [Rate limits](/api-reference/rate-limits). |
| `Retry-After` | `429` and `503` | Seconds to wait before retrying. |
| `WWW-Authenticate` | `401` | The authentication challenge: `DPoP realm="anton", algs="ES256 EdDSA"`, plus `error="invalid_token"` or `error="invalid_dpop_proof"` when a credential was sent and refused. See [Errors](/api-reference/errors#authentication-challenge). |
| `Idempotent-Replayed` | Replayed responses | `true` when the response is a replay of an earlier request with the same `Idempotency-Key`. See [Idempotency](/api-reference/idempotency). |

To correlate a call with your own systems, send `X-Client-Request-Id` (up to 128 characters from `A-Z a-z 0-9 . _ : -`; anything else is ignored). We log it next to ours and never use it as ours.
