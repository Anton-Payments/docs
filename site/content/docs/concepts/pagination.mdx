---
title: "Pagination"
description: "Lists page forward with an opaque cursor. There are no page numbers, offsets or totals."
kind: concept
---

Pass each response's `next_cursor` back as `cursor` until `has_more` is `false`.

## Parameters

| Parameter | Type | Default | Range | Description |
| --- | --- | --- | --- | --- |
| `limit` | integer | 25 | 1 to 100 | Items per page. A value outside the range, or not an integer, is `400 invalid_limit`. |
| `cursor` | string | none | | The `next_cursor` from the previous response. Omit it to start from the first page. A bad or expired cursor is `400 cursor_invalid`. |
| `created_after` | RFC 3339 UTC timestamp, such as `2026-11-01T00:00:00.000Z` | none | | Only items created at or after this time (inclusive). Offered where the endpoint documents it. |
| `created_before` | RFC 3339 UTC timestamp, such as `2026-11-01T00:00:00.000Z` | none | | Only items created before this time (exclusive). Offered where the endpoint documents it. |

Other filters (`status` and so on) are documented with their allowed values on each endpoint. An unknown filter value is a `400`, and an unknown query parameter is `400 unknown_parameter`, never an empty list. A timestamp filter accepts only RFC 3339 in UTC with milliseconds and a `Z` suffix. Any other form, such as an offset like `+02:00` or no milliseconds, is `400 invalid_request` with `param` set to the filter.

Lists are newest first.

## Response

Every list has the same envelope, including short ones such as currencies. A list is never a bare array. A few short lists, such as currencies and event types, are complete and not paged: they return everything with `has_more` `false`.

```json
{
  "object": "list",
  "data": [
    { "id": "pay_01JD3X9K2M7Q", "object": "payout", "status": "completed" },
    { "id": "pay_01JD3X8H4N5R", "object": "payout", "status": "processing" }
  ],
  "has_more": true,
  "next_cursor": "eyJpZCI6InBheV8wMUpEM1g4SDRONVIifQ"
}
```

| Field | Description |
| --- | --- |
| `object` | Always `"list"`. |
| `data` | The items on this page. An empty page is `[]`. |
| `has_more` | `true` when more items exist after this page. |
| `next_cursor` | The cursor for the next page, or `null` on the last page. The key is always present. |

The last page:

```json
{
  "object": "list",
  "data": [{ "id": "pay_01JD3X7G3M4Q", "object": "payout", "status": "completed" }],
  "has_more": false,
  "next_cursor": null
}
```

## Iterating through pages

<CodeGroup>

```bash cURL
# First page
curl "https://api.antonpayments.dev/v1/payouts?limit=100" \
  -H "Authorization: DPoP $ANTON_ACCESS_TOKEN" \
  -H "DPoP: $DPOP_PROOF"

# Next page: pass the previous response's next_cursor as cursor
curl "https://api.antonpayments.dev/v1/payouts?limit=100&cursor=eyJpZCI6InBheV8wMUpEM1g4SDRONVIifQ" \
  -H "Authorization: DPoP $ANTON_ACCESS_TOKEN" \
  -H "DPoP: $DPOP_PROOF"
```

```javascript JavaScript
async function listAllPayouts(accessToken, dpopProof) {
  const payouts = [];
  let cursor;

  while (true) {
    const url = new URL("https://api.antonpayments.dev/v1/payouts");
    url.searchParams.set("limit", "100");
    if (cursor) url.searchParams.set("cursor", cursor);

    const response = await fetch(url, {
      headers: {
        Authorization: `DPoP ${accessToken}`,
        DPoP: await dpopProof("GET", url), // a fresh proof per request
      },
    });
    const page = await response.json();
    payouts.push(...page.data);

    if (!page.has_more) break;
    cursor = page.next_cursor;
  }

  return payouts;
}
```

```php PHP
function listAllPayouts(string $accessToken, callable $dpopProof): array {
    $payouts = [];
    $cursor = null;

    while (true) {
        $query = http_build_query(array_filter([
            'limit' => 100,
            'cursor' => $cursor,
        ]));

        $url = "https://api.antonpayments.dev/v1/payouts?$query";
        $ch = curl_init($url);
        curl_setopt_array($ch, [
            CURLOPT_RETURNTRANSFER => true,
            CURLOPT_HTTPHEADER => [
                "Authorization: DPoP $accessToken",
                "DPoP: " . $dpopProof("GET", $url), // a fresh proof per request
            ],
        ]);
        $page = json_decode(curl_exec($ch), true);
        curl_close($ch);

        $payouts = array_merge($payouts, $page['data']);

        if (!$page['has_more']) break;
        $cursor = $page['next_cursor'];
    }

    return $payouts;
}
```

```go Go
func ListAllPayouts(accessToken string, dpopProof func(method, url string) string) ([]Payout, error) {
    var payouts []Payout
    cursor := ""

    for {
        u, _ := url.Parse("https://api.antonpayments.dev/v1/payouts")
        q := u.Query()
        q.Set("limit", "100")
        if cursor != "" {
            q.Set("cursor", cursor)
        }
        u.RawQuery = q.Encode()

        req, _ := http.NewRequest("GET", u.String(), nil)
        req.Header.Set("Authorization", "DPoP "+accessToken)
        req.Header.Set("DPoP", dpopProof("GET", u.String())) // a fresh proof per request
        resp, err := http.DefaultClient.Do(req)
        if err != nil {
            return nil, err
        }

        var page struct {
            Data       []Payout `json:"data"`
            HasMore    bool     `json:"has_more"`
            NextCursor *string  `json:"next_cursor"`
        }
        json.NewDecoder(resp.Body).Decode(&page)
        resp.Body.Close()

        payouts = append(payouts, page.Data...)

        if !page.HasMore {
            break
        }
        if page.NextCursor == nil {
            break
        }
        cursor = *page.NextCursor
    }

    return payouts, nil
}
```

## Rules

<AccordionGroup>
  <Accordion title="Use the maximum page size">
    Set `limit=100` to cut round trips on large result sets.
  </Accordion>
  <Accordion title="Stop when has_more is false">
    `has_more` is the termination signal. Do not compare `len(data)` to `limit`: the last page can be full.
  </Accordion>
  <Accordion title="Cursors are opaque">
    Pass the exact `next_cursor` you were given. Do not parse, modify or build one: the format is not part of the API and can change.
  </Accordion>
  <Accordion title="Do not keep cursors for long">
    A bad or expired cursor is `400 cursor_invalid`. Start again from the first page.
  </Accordion>
</AccordionGroup>
