description: "Every event wraps the same resource the matching GET returns. Deliveries can repeat, so deduplicate on the event id."

Anton sends an HTTP `POST` to your URL when something happens in your account. Subscribe with `POST /v1/webhooks` and name the event types you want, or `*` for all of them.

You may receive the same event twice, so deduplicate on the event `id`. Retries mean events can arrive out of order: use `created_at` and the resource's own `status`, not arrival order.

Every delivery is signed. [Webhook signing](/concepts/webhook-signing) shows how to verify it. Answer with any `2xx` within 30 seconds to acknowledge receipt. A slower answer, or any other status, a redirect included, is a failed delivery. Anything else is retried up to 5 attempts in all, waiting 30 seconds, 2 minutes, 8 minutes and 32 minutes between them. `GET /v1/webhooks/summary` returns this retry policy.

## The event envelope

Every delivery has the same outer shape. The resource that changed is in `data.object`.

| Field | Description |
| --- | --- |
| `id` | The event ID (`evt_...`). Unique and stable across retries. Use it to deduplicate. |
| `object` | Always `"event"`. |
| `type` | The event type, for example `payout.completed`. |
| `api_version` | The API version the payload is rendered at. See [API versions](#api-versions). |
| `livemode` | `true` for production events, `false` for sandbox. |
| `created_at` | When the event happened, RFC 3339 in UTC with milliseconds. |
| `data.object` | The resource, exactly as the API returns it from the matching `GET` endpoint. There are no separate webhook shapes. |

Each delivery also carries these HTTP headers:

| Header | Description |
| --- | --- |
| `X-Webhook-ID` | The event `id`. |
| `X-Webhook-Event` | The event type. |
| `User-Agent` | `AntonPayments-Webhook/1.0`. The version can change, so don't match it exactly. |
| `X-Webhook-Timestamp` | Unix seconds when the delivery was signed. |
| `X-Webhook-Signature` | One or more `v1={hex}` HMAC-SHA256 signatures. See [Webhook signing](/concepts/webhook-signing). |

### API versions

An event is rendered at the API version your account is pinned to, and records it in `api_version`. A retried delivery is byte-for-byte identical to the first attempt, including its version. A per-request `Anton-Version` header never applies to webhooks. New optional fields, enum values and event types can appear at any version, so ignore fields and types you do not know.

### Intelligence reviews

| Event | When it is sent | `data.object` |
| --- | --- | --- |
| `intelligence.review.opened` | A review opened in your queue, from your own checks or by your team. | Review event |
| `intelligence.review.decision_proposed` | A decision is waiting for a second approver. | Review event |
| `intelligence.review.decided` | A decision took effect, including waiting on your customer. | Review event |
| `intelligence.review.reopened` | A decision was sent back or withdrawn, or your customer responded. | Review event |
| `intelligence.review.closed` | A review closed with its outcome. | Review event |
| `intelligence.review.overdue` | A review passed its due time without a decision. | Review event |
| `intelligence.review.note_added` | A note was added to a review. The note itself is never sent. | Review event |

### Notes on specific events

- `payout.failed` carries a `failure_code` on the payout. A payout we could not process is announced by `payout.failed` with `failure_code` `cannot_be_processed`.
- `payout.on_hold` means the payout is paused. It never says why: `status_message` is the only text.
- `intelligence.review.note_added` never carries the note text.
- `beneficiary.deleted` and `instrument.deleted` carry the ID of the removed object and `"deleted": true`.
- `test` is the type of the delivery `POST /v1/webhooks/{id}/test` sends, to check your endpoint and signature handling. Its `data.object` is a sample payout with `"test": true`.
- Subscribing to `*` delivers every event type, including ones added later.

Events for surfaces your account cannot reach, such as payout events on an account that holds only the `intelligence` capability, are never sent.

## Subscribing

Create a subscription with the event types you want. The signing `secret` is returned once, in the creation response, and cannot be read back.

<Note>
  The `url` must use `https://` and must be reachable from the public internet. Anton refuses plaintext `http://` URLs with `webhook_url_not_https`, and private, loopback and metadata addresses with `webhook_url_private_address`. See [Errors](/errors#webhook-url-checks).
</Note>

```bash
curl https://api.antonpayments.dev/v1/webhooks \
  -X POST \
  -H "Authorization: DPoP $ANTON_ACCESS_TOKEN" \
  -H "DPoP: $DPOP_PROOF" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: webhook-orders-1" \
  -d '{
    "url": "https://example.com/webhooks/anton",
    "events": ["payout.created", "payout.completed", "payout.failed"]
  }'
```

Inspect past events and attempts with `GET /v1/webhooks/events`, `GET /v1/webhooks/events/{id}` and `GET /v1/webhooks/events/{id}/deliveries`.
