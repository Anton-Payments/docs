A case file is one review's formal record as a PDF, for your own auditors and regulators. It is rendered when you ask and never stored. Each call is recorded in your audit log, and once more when the file is rendered, with its size and a SHA-256 of the file.

<BeforeYouBegin items={["The **Audit Pack** add-on, and a credential with the `intelligence` scope and `reviews.view`", "The `irv_` id of a review your account holds"]} />

## Export a case file

<RunStep title="Export a case file" method="GET" path="/v1/intelligence/reviews/{id}/case-file"
  pathParams={{ id: "irv_dbvqsbiukoh4g0rnek30" }}>
  The response is `application/pdf`, with an `X-Export-Id` header.
</RunStep>

`X-Export-Id` is the export's reference in your audit log. Keep it beside the file. The export works for any review your account holds, whatever its status.

There is no `Idempotency-Key` on an export, because each call is a separate audited export. Retrying is safe but it logs another one.

## What an API export leaves out

A case file exported with an API credential never contains note text or the names of your team members. Your people get notes in the case files they export from the portal. If an auditor needs the notes, export from the portal.

## Export reviews as CSV

[`GET /v1/intelligence/reviews/export`](/reference/reviews/export-reviews-csv) returns reviews opened in `[created_after, created_before)` as CSV, with codes, ids and the masked subject only. Both bounds are required, RFC 3339 UTC with milliseconds and a `Z`, and the range is at most 366 days. `status` narrows it. The audit log records the range, the row count and the file's SHA-256, and the response carries the same `X-Export-Id`.

An export that would pass 10,000 reviews is `422 export_too_large`. Narrow the range and export in pieces.

## Retention

Review records are kept for 7 years by default. The period can be extended, beyond 7 years with the Audit Pack, and never shortened. [`GET /v1/intelligence/reviews/settings`](/reference/reviews/get-review-settings) shows `retention_years`.

## When it goes wrong

<Errors>
  <ErrorRow status={422} code="case_file_too_large">The case file is too large to render as one PDF.</ErrorRow>
  <ErrorRow status={422} code="export_too_large">The CSV would pass 10,000 reviews. Narrow the date range.</ErrorRow>
  <ErrorRow status={422} code="invalid_export_range">The range is not valid, for example longer than 366 days.</ErrorRow>
  <ErrorRow status={403} code="module_not_enabled">The account lacks the Audit Pack.</ErrorRow>
  <ErrorRow status={403} code="insufficient_scope">The credential was created without the `intelligence` scope. A missing account capability is `capability_required`.</ErrorRow>
  <ErrorRow status={404} code="resource_missing">The review does not exist, or belongs to another account.</ErrorRow>
</Errors>
