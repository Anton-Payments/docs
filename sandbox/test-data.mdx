To send a payout you need a balance to pay from. In the sandbox you can credit one with a single API call, with no dashboard step and no real money.

## Fund a balance

`POST /v1/sandbox/deposits` credits your sandbox balance in a currency. The credit is additive: calling it twice credits twice. If you have no account in that currency yet, one is created holding the deposit.

```bash
curl https://api.antonpayments.dev/v1/sandbox/deposits \
  -X POST \
  -H "Authorization: DPoP $ANTON_ACCESS_TOKEN" \
  -H "DPoP: $DPOP_PROOF" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: fund-usd-1" \
  -d '{
    "currency": "USD",
    "amount": "1000.00"
  }'
```

Response (`201`):

```json
{
  "data": {
    "id": "sdp_dbvqrpqukoh470i09vfg",
    "object": "sandbox_deposit",
    "livemode": false,
    "currency": "USD",
    "amount": "1000.00",
    "available": "1000.00",
    "created_at": "2026-11-20T02:18:15.202Z",
    "updated_at": "2026-11-20T02:18:15.202Z"
  }
}
```

`amount` is what you credited and `available` is the balance after the credit.

Things to know:

- The endpoint exists only in the sandbox (`https://api.antonpayments.dev`). In production it answers `404`.
- It requires an `Idempotency-Key`. See [Idempotency](/api-reference/idempotency).
- The amount must be positive and use no more decimal places than the currency allows, or you get `422 amount_precision_invalid`.
- A currency the sandbox cannot fund is `422 unsupported_sandbox_currency`.
- Calls are rate limited per account. See [Rate limits](/api-reference/rate-limits).

Check the result with `GET /v1/balances`.

## A typical test run

<Steps>
  <Step title="Fund a balance">
    `POST /v1/sandbox/deposits` in the currency you pay from.
  </Step>
  <Step title="Create a beneficiary and instrument">
    Use `POST /v1/beneficiaries` and `POST /v1/instruments`, as in the [payout guide](/guides/send-a-payout).
  </Step>
  <Step title="Send a payout">
    `POST /v1/payouts`, then watch it move through its statuses by [webhook](/api-reference/webhook-events) or with `GET /v1/payouts/{id}`.
  </Step>
</Steps>

## What is different from production

See the [Sandbox overview](/sandbox/overview). Rail submission is mocked, timing is compressed, and everything else (authentication, validation, idempotency, rate limits, webhook signing and the payout status flow) behaves as in production.
