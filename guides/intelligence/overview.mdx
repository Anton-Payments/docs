Anton Intelligence turns payment-risk inputs into one concise evaluation result. You send a strict request with a `use_case`, an `entity`, and optional instrument or payout context. Anton screens the inputs, scores the risk, and returns a decision.

The create endpoint is intentionally strict. Unknown fields are rejected, enum values are fixed, and sensitive values are used only in memory. Anton persists redacted decision evidence, not raw PII. Every response includes `contract_version: "intelligence-public-v1"` so clients can pin and generate SDKs against a stable schema.

## Authentication

Every Intelligence route requires OAuth + DPoP credentials with the `intelligence` scope — see [Authentication](/authentication). There is no anonymous surface; a request without credentials returns `401`. Evaluations persist under **your** merchant account; read them back via the scoped [list](/api-reference/intelligence/list-evaluations), get, and evidence endpoints. `Idempotency-Key` is **required** on create. To try the API, use your sandbox credentials.

Intelligence is available on **every** account tier — including [AI-compliance-only accounts](/capabilities) that have no payout surface. Start with the [quickstart](/guides/intelligence/quickstart) for the full authenticated walkthrough.

## Use cases

| Use case | When to use it | Event type |
|---|---|---|
| `payee_registration` | Registering or screening a person or business payee | `payee.create` |
| `instrument_screening` | Adding or screening a bank account, wallet, card, or IBAN | `instrument.create` |
| `payout_screening` | Evaluating payment movement context | `payout.create` |
| `merchant_onboarding` | Evaluating business onboarding data | `merchant.onboard` |
| `monitoring` | Generic/manual screening | `monitoring.evaluate` |

## Required shape

```json
{
  "use_case": "payee_registration",
  "entity": {
    "type": "person"
  }
}
```

For a meaningful evaluation, include at least one searchable input: `entity.name`, `entity.vault_token_id`, `instrument.vault_token_id`, or the matching instrument fields.

## Validate before creating

Use validation to test request shape without creating an evaluation:

```bash
curl -sS -X POST "https://api.antonpayments.dev/v1/intelligence/evaluations/validate" \
  -H "Authorization: DPoP $ANTON_ACCESS_TOKEN" \
  -H "DPoP: $ANTON_DPOP_PROOF" \
  -H "Content-Type: application/json" \
  -d '{
    "use_case": "payee_registration",
    "entity": {
      "type": "person",
      "name": "John Doe",
      "country": "US"
    }
  }' | jq
```

## Field rules

| Field class | Rule |
|---|---|
| Countries | Uppercase ISO 3166 alpha-2, such as `US` or `CA` |
| Dates | Real calendar dates in `YYYY-MM-DD` format |
| Currencies and assets | Uppercase supported currency or asset codes, such as `USD` or `BTC` |
| Instrument payloads | The nested payload must match `instrument.type` |

## The evaluation

The response is an evaluation: `id` (`eval_...`), `object`, `livemode`, `status`, `use_case`, and the result fields below. See the [quickstart](/guides/intelligence/quickstart) for a complete example.

| Field | Meaning |
|---|---|
| `coverage` | How much of the screening panel answered: `complete`, `partial` or `error`. |
| `decision` | `approve`, `review` or `decline`. See [Decisions](/guides/intelligence/decisions). |
| `score` | Risk score from 0 to 1000. Higher is worse. |
| `tier` | The score's band: `low`, `medium`, `high` or `critical`. |
| `reasons` | Why the decision is not a plain approval. Empty for a clean approval. |
| `required_actions` | What you can do about it. |
